# M3 项目清单与归档目标设置网页

方案 A 第十四个增量。管理员在现有 Project settings 页分别维护交接清单和允许归档的目标目录。
沿用现有 GET/PUT、C++ 权限和修订检查，不新增 MCP 工具、服务、数据库迁移或模型调用。

## 操作与外发边界

- **Load / refresh checklist**：读取完整清单及当前修订；可增加、修改、删除必需/可选项。
  key 是稳定标识（小写字母开头，后接小写字母、数字、下划线，最多64字符），不从标题自动推断。
  最多50项；标题1–200 UTF-8字节，描述0–1000字节，单行且不接受控制字符。重复key在保存前拒绝。
- **Load / refresh archive directories**：读取完整策略及当前项目已有目录，勾选最多100个目标。
  同名目录显示稳定ID帮助区分，保存当前所见名称，不提交用户输入路径。创建/改名目录仍用现有业务API；
  本轮只提供目标选择，不新增目录管理功能。
- 每份配置独立保存、独立修订；清单为空或目录全不选明确清空对应集合，不删除文件或目录。
- 当前批准状态只作展示。编辑草稿的外发勾选始终默认关闭，加载批准过的配置也不会继承勾选。
  编辑文字、必需标志、增删条目或选择目录均撤销勾选；必须在完整编辑后重新批准。
- 勾选后保存是管理员对本次完整元数据的外发批准；不勾选保存会撤销旧批准。
  不改变文件版本批准、不确认归档方案、不执行文件移动，也不启动模型。
  变更修订/撤销批准可能使绑定旧修订的任务、回答或报告不可访问，页面明确提醒。

## 并发、错误与权限

保存仅发送读取到的 `expected_revision`、完整 `items` 或 `targets` 以及明确的 `confirm_remote_ai`。
目录名称来自当前目录列表；外部改名导致旧策略失效时先重新读取，再审阅新名称和明确重新批准。
清单/目录服务端契约见[清单](m3-handover-checklist.md)与[归档策略](m3-archive-preview.md)。

保存期间禁用该编辑器及刷新，锁持续到实际请求结束；切换项目或注销不能解除在途写锁。
读取先清旧草稿；只有最后一次仍属于当前项目/角色的响应能渲染。
刷新会放弃未保存修改，按钮附近明确提示。所有保存结束均清草稿，后续编辑须显式重读。
冲突、权限拒绝或响应丢失不自动重试/覆盖，只提示核对实际修订，不把超时当作未提交。

项目切换、注销（包括开始注销时）、已确认的本人角色变化会清空设置并使旧响应/按钮失效。
本页沿用管理员可见设置入口；reader/editor不能操作编辑器，即使篡改网页仍由C++拒绝PUT。
其他管理员的变更不会实时推送到页面；每次读写仍由服务端执行当前权限与修订检查。
设置写请求发起及结束都会使本页相同项目的Agent草稿/配置/结果快照失效，防止继续使用本页旧配置。
没有localStorage草稿、HTML解释、自动模型请求或自动归档。

## 验证与范围

使用原生输入框、checkbox、fieldset 和已有移动端布局，不新增前端依赖。
新增模块 `/js/project-settings.js` 已加入 C++ 精确静态白名单；升级时须同时构建后端并更新网页资源，
仅复制前端文件到旧服务会使模块加载失败。无需新增数据库迁移。
[验证证据](../evidence/m3/project-settings-ui/README.md)记录实际测试结果与服务器限额。
本轮不代表完整M3/P0验收；目录管理网页、受控执行入口、固定任务效果评测和完整演示仍需后续工作。
