# M3 网页任务模式与修订绑定

方案 A 第十三个增量。复用原生页面和既有 C++/schema15 接口，无新服务或依赖。
创建仍只是 pending；不启动模型、自动确认或移动文件。

## 使用

在 File detail 选择 1–100 个明确获批的当前版本，填写问题并选择模式：

| 模式 | 当前角色 | 附加信息 |
| --- | --- | --- |
| Question and answer | 项目成员 | 不加载/附加清单或目录策略 |
| Handover check | 包括 reader 的项目成员 | 已批准且非空的交接清单修订 |
| Archive proposal | editor/admin | 已批准且非空的归档目标策略修订 |

交接/归档须点击 **Load / refresh approved configuration**，查看修订及完整条目/目标。
清单展示必需/可选、标题和描述；归档展示目标名称和稳定目录 ID。内容全部作为文本显示。
随后用户明确勾选外发确认：问题、选定版本及所见模式配置可以发给远程供应商。
此勾选不是移动确认，归档仍需后续逐项查看具体方案、确认具体修订、独立执行。

网页只向任务 POST 添加 `handover_checklist_revision` 或 `archive_policy_revision` 之一；
不提交模式字符串、清单正文、目录名称或自填批准。修订来自刚读取的服务端响应，非可编辑字段。
普通问答不提交额外字段。C++最终重验身份、角色、文件范围及配置修订，不能以网页检查代替授权。
不存在/空/未批准配置或读取失败时不创建任务，不自动降级为问答。
管理员可通过后续新增的[配置网页](m3-project-settings-ui.md)维护，也可使用[清单接口](m3-handover-checklist.md)和[目录策略接口](m3-archive-preview.md)。

## 变化、冲突与恢复

切换模式/刷新配置清空旧配置并撤销外发勾选；问题和版本范围变化也撤销勾选。
配置读取完成时仍须重新勾选。项目/角色变化、注销、新草稿和文件数据失效清空模式/范围，
使所有迟到配置响应失效；并发读取仅最后一次有效。不缓存到 localStorage。
页面是手动访问快照，不实时监听别的用户修改。后端拒绝过期修订，不自动升级到新配置。

提交期间锁定模式、配置刷新和其他创建动作；切换项目不能释放在途创建锁。
创建失败清配置、撤销勾选并保留“结果可能未知”，不自动重试非幂等创建。
先刷新本人任务核对实际结果，再显式 New draft；切换模式不解除未知结果保护。
即使错误明确为修订冲突，当前也采用同一保守恢复流程，不偷偷重发。
