# M3 管理员逻辑目录网页

方案 A 第十七个增量。在 Project settings → Logical directories 中先加载当前目录，
再选择父目录创建子目录，或在非根目录卡片改名。显示稳定 ID 和父目录 ID 区分同名目录。
复用原有同项目 GET/POST/PATCH 接口，不新增 MCP 工具、依赖或迁移。

## 边界

- 只有 admin 可编辑；reader/editor 即使绕过网页仍被 C++ 拒绝。
- 根目录没有改名表单。目录名为去首尾空白后的 1–255 UTF-8 字节，拒绝斜杠和控制字符；
  服务端仍是名称、父目录、重名和权限的最终权威。
- 仅创建及改名，不删除/移动目录，不移动文件、不改变版本批准、不调用模型。
- 改名已批准的归档目标会由 C++ 撤销策略批准并递增修订，绑定旧修订的任务不能继续使用。
  页面立即清除旧归档配置、批准提示和 Agent 草稿/结果；需重新加载策略并审阅后单独批准。
  名称本身只是数据，使用 textContent 展示，不解释为 HTML 或授权。

## 并发与恢复

加载/刷新会丢弃目录编辑草稿，并使本页旧归档配置、Agent 和检索结果失效。
只安装当前项目最后一次成功读取的目录快照；切换项目、本人角色变化和注销清空视图，迟到响应不能回填。
写锁持续到请求实际结束，不能用切换项目或注销绕过，旧卡片按钮也不能再次提交。

每次写入结束最多重新 GET 当前目录列表；绝不重试 POST/PATCH。网络失败只提示结果可能未知，
清除创建草稿并要求核对权威列表；不能把超时理解成未提交。读取失败则禁用编辑，等用户显式刷新。
刷新更新上传/移动/过滤选项与文件列表目录名称，保留仍存在的目录 ID 和上传目标文件 ID。
未使用实时推送，其他管理员的操作在重新读取后可见；每次实际写入仍重验权限。

## 验证与部署

复用现有 project-settings.js 静态模块和移动端单列布局。对已有 A16 版本只需更新网页资源，
无需重建 C++ 或升级 schema；更旧服务仍须满足[项目配置模块的静态路由要求](m3-project-settings-ui.md)。
本轮测试及限制见[证据](../evidence/m3/directory-ui/README.md)。未执行生产部署，也不代表 M3/P0 验收完成。
