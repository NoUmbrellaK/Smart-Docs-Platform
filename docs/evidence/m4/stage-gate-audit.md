## 初次明确缺口：方案调整没有网页入口（历史）

需求A-02第4步要求用户能拒绝计划，或要求调整后生成新的计划修订。
当前代码链路：

| 层 | 当前行为 | 证据 |
| --- | --- | --- |
| 网页方案 | 只读展示项目；只有确认、拒绝、执行及回执按钮；rejected只显示需要新修订 | [agent.js](../../../resources/js/agent.js)的renderArchive |
| 网页API | 有GET方案、POST决定/执行及GET回执，没有PUT修订封装 | [api.js](../../../resources/js/api.js)的archivePath相关函数 |
| 再次运行模型 | 网页仅pending显示启动；后端StartRun拒绝非pending；归档Agent只允许expected_revision=0 | [agent_tasks.cpp](../../../code/agent/agent_tasks.cpp)、[agent_runner.py](../../../python/smartdocs/agent_runner.py) |
| 已有新修订能力 | PUT检查expected_revision，沿用同一plan_id递增revision，重新等待确认，旧操作不能执行新修订 | [archive_plans.cpp](../../../code/agent/archive_plans.cpp)、[HTTP边界用例](../../../test/e2e/m3_archive_execution_test.py) |
| 历史浏览器证据 | 拒绝由浏览器点击；新修订由测试代码直接PUT，再返回网页确认 | [浏览器测试](../../../test/e2e/m3_agent_browser_test.py)中的proposal更新；[历史记录](../m3/archive-ui/README.md) |

创建另一条任务可另起一次提案，但不是同一plan_id的新修订，也不会解决等待中的原任务。
不通过放宽StartRun、让模型伪造确认或自动开启新收费请求绕过此缺口。

下一实现增量应复用既有PUT接口，提供受控的方案调整：保持文件/版本/源目录绑定，
目标只来自本修订的已批准策略，允许显式待确认目标，修改理由后保存新修订。
保存不能确认或移动文件；新修订必须重新勾选确认。过期修订、权限/策略变化、取消、
在途写入、迟到响应和响应丢失必须沿用现有失败关闭规则；不自动重试。
须用真实浏览器完成调整操作，而不是继续由夹具代发PUT。
这只是下一增量的边界，不代表入口已经实现；是否增加自然语言再次编排不影响此处
必须先补的真实用户操作能力，也不能将手工调整称为模型重新分类。

独立只读审查已复核上述缺口，并确认[现有接口说明](../../api/m3-archive-execution.md)
也注明尚无方案编辑器或模型修订入口。审查没有修改文件、运行测试或访问模型。
人工调整应明确标注为人工操作；如果另行要求“提交自然语言反馈，由模型重新分类”，
还需独立的修订绑定、持久状态和累计预算设计，不能冒充已由人工编辑入口覆盖。
