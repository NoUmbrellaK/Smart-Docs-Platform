# M2 预初始化模型复用实验

日期：2026-10-17；生产与组合测试基线 `e00c2edb207d8794cfc2c95bcce0dd51d5d82888`。
这是用于验证[冷加载诊断](../encoder-cold-start/README.md)的临时原型，不是生产实现、
部署建议或 M2 阶段验收。生产代码、组合测试、模型、依赖及数据库结构均未修改。
没有读取 DeepSeek 凭据或调用远程 API。

## 实验控制与变化

同一 ECS、同一非 root 账号、同一模型锁及共享资源组；预热也在该组内，不能把预热
成本藏到资源限额之外。MemoryHigh=1200MiB、MemoryMax=1600MiB、SwapMax=0、
CPUQuota=100%、TasksMax=256，/dev/vda 读写各 5MB/s、200IOPS、Nice=10。
编码原型 PrivateNetwork=yes、RestrictAddressFamilies=AF_UNIX、NoNewPrivileges=yes，
启动时实际探测 IPv4/IPv6 socket 被拒绝，目录 0700、接口 0600。

原型先调用原 `_encode` 完成真实模型初始化和一次人工文本推理，成功后才创建私有
socket 并发送 systemd READY。初始化单独设 180 秒上限；启动完成后服务总寿命上限
900 秒。不是把原单请求 60 秒上限提高到 180 秒。浏览器测试单元最长 780 秒。

唯一缓存对象是固定参数的真实 TextEmbedding 实例；后续每个请求在 fork 子进程中
执行原 `_encode`，仍完整校验全部模型文件 SHA、依赖版本、CPU provider、输入、
窗口覆盖、向量归一化和结果结构。没有伪造模型响应或永久跳过完整性检查。
每次只处理一个请求，保留 60 秒执行截止期，超时杀进程组并等待回收。

同时改变的因素还包括预先导入依赖、先完成一次推理，以及子进程写完结果后使用
`os._exit`，不执行常规 Python 退出清理。因此即使结果改善，也不能把全部差异
归因于模型构造缓存，或把它当作严谨的单变量性能基准。

## 生产化前的边界

- 预热后观察到父进程 Threads=1，不等于 ONNX/tokenizer 在任意版本、配置和负载下
  都可安全 fork；本轮只覆盖锁定版本及小型人工输入。
- 常驻父进程仍有累计 CPU 60/65 秒限制，原型仅接收最多 32 个连接；这不是可直接
  长期运行的服务生命周期设计。无自动重启、持久排队或并发吞吐量承诺。
- 模型缓存只供固定路径、固定哈希和参数使用。不支持热替换；每次文件校验成功
  不等于原子地绑定磁盘文件和已加载会话。生产方案需约束模型只读、启动及升级。
- 60 秒是父进程的墙钟监督预算，不是严格实时响应保证；不可中断的内核 I/O、
  kill/reap 和返回结果仍可能延迟。当前原型没有故障注入覆盖此边界。
- 私有同账号 socket 是可信本机边界，不是用户鉴权接口。真实 C++/worker/网关
  继续执行批准范围及发布检查；原型不代替这些检查。
- 错误映射、畸形协议、断连、长期内存变化、重启和超时后恢复尚未完整验证。
  不把成功路径的一次实验代替生产 TDD、安全测试及重启回归。
- 原型用 `assert` 检查若干启动条件，只能按本轮未启用优化的可信命令运行；
  不能直接照搬成生产安全校验。没有对同一输入重复请求做一致性测量。
- 父进程 RSS 不是父子并存的总内存。共享组包含浏览器、数据库、编码父子进程及
  文件缓存；本机内核没有 `memory.peak`，定时 `memory.current` 采样仅是观测值，
  不能冒充精确峰值。没有给模型目录增加新的只读挂载，实验期间未修改模型文件。

## 实测结果

首轮：先预热模型，再启动数据库和浏览器。初始化 58.387 秒，父进程峰值 RSS
752616 KiB；后续归档采样 NLWP=1、RSS=730940 KiB。组合测试 **0/1**，
106.103 秒，在 `browser.start()` 返回 `WebDriver session not created`，没有发送
编码请求，不能评价预热后的请求耗时或搜索效果。测试单元北京时间
23:21:06–23:24:33，退出码 1；schema 5 和 103 文件升级夹具通过。
见[测试输出](first-browser-check.txt)、[初始化事件](first-encoder.jsonl)、
[分段内存采样](first-memory-samples.txt)。本轮结束后停止预热服务，两者 MainPID=0，
无运行中 smartdocs 临时单元，mysql active；memory.high 从 27699 增至 30790，
max/oom/oom_kill 均为 0。不能直接把 Chrome 启动错误判作内存不足。

第二轮只调整实验启动顺序：[临时包装器](browser_then_warm_spike.py)先调用真实
`Browser.start()`，打印明确就绪信号后，最多等 240 秒私有 socket；主代理看到信号
才启动同一预热原型。socket 在真实初始化完成后才出现；原测试全部业务断言不改，
不跳过 Chrome 沙箱、模型校验或失败状态。这个等待是测试准备屏障，不改变请求
60 秒/客户端 75 秒预算；初始化仍由单元独立限制为 180 秒。

23:26:50 及启动前检查新路径 `warm-ordered.sock` 不存在；23:27:57 观察到 browser
ready 日志（时间为观察时间，不是事件精确发生时间；命令输出转录见
[定点记录](resource-observations.txt)），模型单元 23:28:17 才启动。屏障只检查 socket 类型/权限/所有者，不是
完整 READY 协议，bind→chmod→listen 之间有短暂竞态，可能造成假阴性；它不能
伪造实际业务结果。重跑必须使用新的私有路径，不能把陈旧 socket 当作存活证明。

第二轮：浏览器先启动成功，模型初始化 **137.891 秒**，峰值 RSS 743572 KiB。
模型单元 READY 时间 23:30:38；随后实际处理任务的 `/claim` 发生
`worker_transport_failed`，tearDown 的取消请求也出现 `TimeoutError`。
组合测试 **0/1**，337.425 秒、2 个错误；不是两个测试失败。
见[测试输出](ordered-browser-check.txt)、[模型事件](ordered-encoder.jsonl)和
[READY 时单元状态](ordered-ready-status.txt)。

`worker_transport_failed` 合并了多种传输异常，本轮没有保留底层异常分类，不能
断言 claim 必然是 30 秒超时、数据库故障或鉴权问题。采样曾看到测试 Python 等待
`wait_on_buffer`，临时 MySQL/Chrome 等待 `wait_on_page_bit_common`，见
[定点观察转录](resource-observations.txt)；这只表明
存在 I/O 等待，不能替代请求级根因跟踪。清理过程中仍有 Chrome 和临时 MySQL
进程，23:34:17 停止预热服务后共享组用量降至约 523 MiB；随后显式停止测试单元
以回收余下子进程，最终退出码 1，23:34:51 完全结束。不是正常全通过退出。

两轮都没有进入真实编码请求，日志只有初始化事件，故 **fork 请求复用、60 秒
回收和真实搜索效果本轮均未得到动态验证**；没有成功截图。不能根据初始化成功
宣称“预热后的请求更快”、浏览器直通模型已通过，或生产服务已修复。

第二轮[分段采样](ordered-memory-samples.txt)最大观测 memory.current 为
1275121664 bytes（约 1216 MiB），不是全程精确峰值，也没有父子编码并存样本。
memory.high 本轮合计 27699→35671（第二轮 30790→35671）；max/oom/oom_kill
均为 0，存在内存节流，不是“没有内存压力”。最终四个临时单元均 MainPID=0，
无 running/activating/deactivating smartdocs 单元，已知进程消失，生产 mysql active，
见[终态与限额](unit-status.txt)。

## 复现、审查与后续

[原型](warm_encoder_spike.py)仅作为历史实验源归档，不导入生产 Python 包，不安装
服务。必须通过上述非 root、禁网、受限的 Type=notify 单元运行；四个位置参数依次
是可信 Python 源目录、固定模型目录、新的私有 socket 路径和既有模型锁路径。
使用模型虚拟环境的 `python -I -B`，NotifyAccess=main、UMask=0077、KillMode=control-group。
第二轮在原测试环境变量下，将 `test-with-mysql.sh --` 后的测试入口临时换成
`browser_then_warm_spike.py`；等待真实 browser ready 信号后再启动模型单元。
包装器含本机绝对实验路径，不能作为通用部署命令直接照搬。

[源哈希](source-sha256.txt)绑定本轮 16 个生产/测试文件和两个实验脚本；前 16 个与
非 root 副本逐个 cmp 相同，两份实验脚本与实际运行的临时文件相同。两个脚本语法
检查通过；未重跑 Python/JS/C++ 全套，不借用前轮数字作为本轮成绩。只读审查
核对了断言未改及上述生命周期/证据限制；这不是运行验收通过。
驱动原始日志可能含登录参数，不归档；仅保存无凭据的测试输出与资源/阶段记录。

本轮结论：在原共享限额下，“把初始化移到请求前”可以完成初始化，但尚不足以
让浏览器、数据库及模型组合场景通过。下一步先量化常驻模型可回收内存及
初始化对本机 HTTP/数据库延迟的影响，再决定最小实现；不要直接上线这个 fork
原型、延长请求超时、循环重试或根据这两次实验要求物理扩容。
生产代码仍保持原样，M2 阶段仍未关闭，未进入 M3。
