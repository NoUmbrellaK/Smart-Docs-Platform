## 原因与边界

任务状态中的`archive_policy_revision`表示创建任务时选择了归档策略，并不表示已有方案。
A07冻结判据允许后端拒绝同名冲突、任务`failed/scope_changed`且方案数0。
原采集器只要看见策略修订就要求`GET archive-plan`返回200，因此会把这一分支记为采集失败。

现在仅当任务及run/result均为`failed`、结果没有报告/归档回执kind时允许方案入口404，
保留`archive_plan: null`、原失败状态/错误码及HTTP观察，并在末尾再读一次。
404→200、200→404或其他已观察对象变化仍使采集不完整；403/409/503不被放宽。
等待确认、等待执行、已完成或有归档回执的任务仍要求正常读取方案。
失败任务若仍有方案，保留实际200结果，不能丢弃它。

404也可能来自权限/依赖校验，因此这里只说明“两次未读到方案”，不证明SQL中方案不存在，
也不证明A07业务通过。真实业务评审仍需后端冲突工具轨迹、任务状态、方案数量及文件未动证据。
采集仍只发GET；不会完成任务、确认或执行归档，不保存错误响应正文。
