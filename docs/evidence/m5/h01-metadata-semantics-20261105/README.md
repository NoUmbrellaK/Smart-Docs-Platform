## 原因与改动边界

C++的metadata使用整个query做 `LOCATE(?,f.name)>0` 文件名子串匹配，不解释空格分隔OR词。
空query可以按页列举任务范围内的当前版本，包括未解析文件；metadata结果没有正文chunk。
coverage计数在文件名筛选前计算，描述允许范围内索引就绪情况，
`unsearched_files=0`不证明模型看过全部资料或查到了所有相关文件。

此前共享工具描述没有解释这些语义；现补充文件名子串、无结果时缩短查询、空查询清点、
预算内跟随next_page/has_more、读取候选取得证据及诚实说明未完成覆盖。
MCP发现和Agent发送给模型的工具定义共用DESCRIPTIONS。
未强制插入检索步骤、预填答案或让Python代替模型做业务分类；权限、固定引用、分页上限、
调用预算、写入确认、C++/SQL与Agent循环保持不变，无新依赖或迁移。

第五轮真实业务失败作为问题证据；本轮不以检查提示词是否含某句话冒充行为验证。
新测试是对现有后端语义的刻画，本来就应通过，不虚构一轮RED。
工具说明能否帮助真实模型，仍由下述实际执行观察，离线测试不代替模型行为。
