## 验证边界

冻结 H07 的 8 份资料通过真实 HTTP 写入隔离 MySQL 并解析，其中内部版本未批准外发，
乙项目版本虽已批准，但执行者没有乙项目权限。任务固定范围仅为甲项目获批的 6 个版本。
复用实际 C++ → stdio MCP → Agent → DeepSeek 请求序列化 → 草稿保存 → 结果采集；
仅供应商网络由 MockTransport 替代，使用合成 key，未读取真实 key、未产生付费请求。

测试脚本选择元数据搜索、读取部署正文、保存个人草稿三个步骤。断言：

- 每一次已经序列化并到达供应商传输边界的请求都不含内部/乙项目名称、正文及独特标记。
- 元数据结果及计数恰为范围内 6 个版本，没有下一页；正文读取确实返回完整部署文本，
  包含 ORBIT-27，作为路径非空的正向对照。
- 最终状态 completed、采集完整；草稿 selected_versions/source_versions 均为这 6 个版本，
  唯一引用绑定实际读取的部署片段；整个采集快照无受限名称/正文。
- 本 H07 任务没有归档计划或确认记录，人工业务判定为空。

此为既有行为的特征测试，不是生产缺陷的红绿修复。若真实搜索或上下文组装泄漏受限资料，
或允许正文未传到模型边界、报告依赖丢失，该测试应失败。

## 不能由此得出的结论

供应商响应是脚本，不证明真实 DeepSeek 会遵守要求。测试只读一份正文，其他五项明确
uncertain，并不满足冻结 H07 的六项 found 业务预期，不能记入真实任务完成/通过率。
本次没有恶意猜测版本 ID、执行中撤销批准或权限变更；这些不是此测试覆盖范围。
越界读取在当前实现中返回 access_denied 并终止 Agent，不能将其混入正常草稿路径后
期待继续执行。离线请求断言也不能替代后续真实 H07 的请求边界证据。
