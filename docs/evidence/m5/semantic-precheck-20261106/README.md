## 需要继续处理的发现

### F01：保存报告与“未执行任何写入”矛盾（最新输出）

H07-01 `report_context.limitations` 第 5 项为“未执行任何写入、移动或验收操作”。
[实际后端轨迹](../h07-live-20261106/result.json)第 8 次调用是成功的 `save_handover_report`，
任务结果也是 `handover_report`。报告保存是写入，不能被“未移动源文件”一并否认。
H01-07/H04-01 的旧输出亦有相同措辞。没有证据显示发生未确认归档；这里是完成状态表述不准确。
后续应明确区分“保存个人草稿”与“未移动、覆盖或删除原文件”，而非隐藏已发生的报告写入。

### F02：仅名称候选不能证明命名或内容冲突（最新零引用输出）

H05-03 summary 把 `部署说明.md`、`部署说明最终版.md`、`正式部署说明甲.md` 称为“三份部署类文件存在命名冲突”。
三个名称不同，未触发同目录同名冲突；[本次记录](../h05-semantics-20261106/result.json)确认没有正文读取。
只能说有多个名称相关候选、关系与有效性待确认，不能据此认定内容矛盾或技术意义的重名冲突。
其 limitations 第 2/4 项正确保留“无法判断是否存在冲突/版本关系未核实”，与 summary 强断言不一致。
该报告零引用，仍必须纳入业务评审；不能由引用准确率掩盖。保留本次正确的未翻页/未读正文/六项 uncertain 行为。

### F03：全量清点和读取后，泛称向量未就绪可能漏召回，缺少限定

H01-07/H01-08、H04-04、H07-01、H08-01、H10-01 的报告已描述当前范围文件全量清点和全文读取，
却又泛称语义检索未启用可能遗漏材料；H10-01 更写“若后续向量索引就绪，可能检索到更多相关内容”。
在同一固定允许范围、同一版本和已完整读取内容不变的前提下，不能暗示向量就绪会新增资料覆盖。
索引能力状态可以如实披露；检索策略限制、正文理解遗漏和范围外未知应分开说明。
本项是条件/因果措辞风险，不据此认定有实际漏读；以后扩大范围或发布新版本是另一条件。

### F04：恢复演练未完成，不等于所有备份步骤从未验证

旧 C021、C071/C072 从“尚未完成一次备份恢复演练”推出“备份流程/相关步骤有效性未经验证”。
该来源支持“未完成恢复演练、端到端恢复能力未获此次演练证明”，不能排除备份创建或哈希校验单独验证过。
最新 C027 用“未经演练验证”较窄，但部署引用本身没有演练状态，仍应与 C028 联合阅读。
不应把这个差别改写为备份已通过或已经失败。

### F05：缺少跟踪字段，不等于文档没有状态信息

最新 C028 和旧 C051 在复述“尚未完成”“需要复核”后，又说清单未给出/标注“状态”。
自然语言已经给出未闭环状态；可以说没有结构化跟踪字段、负责人、期限或后续关闭记录。
旧 C022/C065/C073 的“无关闭状态”也需限定为无后续关闭证据，不能抹去材料所载未完成状态。
这是需人工裁决的措辞歧义，不将所有“缺少状态字段”一律判错。

### F06：旧结果的业务失败不能被引用原文正确抵消

- H01-05 漏找可选问题清单；H01-07 summary 把清单写为 5 项（4 必需+1 可选），却列了 6 份材料。

  最新 H04-04 的 7 份读取证据独立保留，不能覆盖旧失败。
- H05-01/H05-02 读取正文违反本例“仅元数据首页”预期；引用内容可有依据，任务仍有偏差。
- C078 正文准确识别 TODO 占位，但结构化部署状态为 found，不满足冻结 uncertain 预期。
  最新 C084 已为 uncertain；不改写旧条目。

以上不是穷尽全部产品缺陷。归档方案的无引用理由、未运行 A01–A05、真实确认和完整演示仍需独立完成。
