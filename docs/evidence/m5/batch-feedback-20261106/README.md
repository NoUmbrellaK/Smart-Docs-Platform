## 改动与边界

- 通过响应大小、外层及正文类型校验后，首次`tool_calls`列表超过4项时整批丢弃。
  不拆分执行，不记工具调用ID，不把被拒参数/正文放入历史，不扣未派发的工具次数。
- 下一请求携带一次固定`runtime_batch_rejection`提示，让模型自行重新选择调用；
  后续不重复该提示。每运行最多一次机会，第二次超限仍`model_invalid`。
- 原8次模型循环、12次工具、180秒、单次64KiB/累计512KiB及适配器自有额度不变。
  纠错请求照常计数/计费，提示计入字节门禁，发送前再次验证全部回执与任务上下文。
  撤权、预算不足、审计失败均停止；混合写批次仍拒绝，无工具重放、自动归档确认或执行。
- 新私有事件仅含序号和封顶5的计数，区别于终止性`model_rejection`。
  汇总要求纠错attempt→成功result后才接受工具或完成；缺失/失败响应不能伪装成功。
  没有新事件的旧轨迹不新增汇总字段，不回写历史失败或业务判定。
