## 诊断与最小改动

沿调用路径检查 C++ start 返回 → `run_task` user消息 → MCP结果 → DeepSeek请求：
用户问题原样置于user角色，工具结果保留分页标志，清单/资料不升为system。
新增离线路径测试在修改提示之前即 **1/1通过**（0.631s），排除了该受控路径上的
问题丢失、分页字段丢失或无法保存无引用草稿。它不是新发现的失败测试，
也不能证明历史真实供应商请求原文：H05没有保留原始请求抓包。

代码中报告运行时system指令此前无条件要求“预算允许时读取未读候选”；
通用补充检索建议也未显式服从用户限制。与元数据-only要求存在指令冲突。
可确认的是这段提示存在且沿该路径发送，不能据此断言模型内部唯一因果。
真实H05失败是本次修复的可复现输入/观察基线，尚未进行同输入修复后实测。

按最小实现原则仅调整三处提示文字：

- 通用搜索/读取建议服从用户的搜索模式、分页与正文限制，工具可用和预算剩余不扩大范围。
- 元数据核查可在备注列候选名，但未经正文核查的项保持uncertain；分页未完成时，未见项目不能据此判missing。
- 运行时阅读记录只在用户允许内容检查时建议继续读取，并保留保存报告所需预算。

普通“检查交接资料”的请求仍允许必要读取，不要求额外逐次确认。
不从自然语言关键词推导权限，不加入H05特判，不改冻结问题/输入/期望，
不把用户文字或工具内容提升为system，不新增服务端检查策略或第二套权限。
既有参数校验、来源重验、引用门禁、预算和归档确认全部不变。
这不是硬性metadata-only工具封锁，也不能保证任意模型都遵守自然语言限制。
