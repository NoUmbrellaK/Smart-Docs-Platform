# 只读执行核心审查

独立只读审查覆盖 C++ 生命周期/权限/迁移、Python 预算/来源/失败收敛和测试边界。
不将审查意见当作运行结果；实际 RED/GREEN 另存日志。

最终复核：明确invalid_source只来自已收到的权威HTTP错误，正确进入failed/null；
传输不确定仍只重放相同completed。复核未发现剩余实质问题，不等于生产验收。

已处理问题：

- 领取前范围已失效时，原顺序只写 failed 而没有 agent_runs，结果查询变404。
  先在同一事务建立运行记录，再检查范围；新增真实 C++ 结果查询回归。
- 完成响应丢失后不能提交相反 failed，也不能将 completed 和失败码拼接返回。
  先保留已提交结果；进一步用线程接收器复现 GET 越过尚未提交的 finish。
  现在仅重放一次完全相同的幂等完成请求，再查询结果，仍不确定返回 unknown。
- 服务端明确拒绝 invalid_source 与网络不确定性不同，需要以 failed/null 收敛。
  增加单独回归验证，不能反复提交被拒绝的结果并遗留 running。
- 补足 12 次工具和 64 KiB 请求上限；512 KiB 累计上限也由8次×64KiB约束。

测试夹具修正：

- SQL 夹具没有真实原文件，重启时原件校验正确地将其标为 unavailable；未绕过校验，
  把完成结果跨重启持久性断言迁入真实上传/解析 E2E。
- MCP 异步上下文会包装异常，ValueError 断言改在上下文内部；工具预算场景使用
  不重复的调用 ID，防止先撞到格式错误而没有验证预算。

明确未解决为生产能力的边界：真实供应商与取消、内部认证传输、逐调用持久审计、
网页、查询向量接线及三个写工具。直接拥有用户会话者可以提交本人的草稿结果，
因此当前 API 不是服务端执行证明或已审计交接报告。没有新增权限数据库或执行框架。
