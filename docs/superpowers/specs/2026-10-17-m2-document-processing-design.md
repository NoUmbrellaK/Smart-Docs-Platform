# M2 文档处理与检索设计（方案 A）

用户已于 2026-10-17 选择方案 A。需求文档是唯一验收基线；本文固定实现边界，不表示功能已完成。沿用用户要求：小问题自行决定，当前服务器执行，正常验证后提交推送；不重复请求常规实施许可。

## 1. 架构与范围

- C++ 继续作为项目权限、文件版本、任务状态、索引发布和写操作的唯一权威。
- 复用 MySQL 保存持久任务、版本处理状态、片段和关键词索引，关键词采用 InnoDB ngram FULLTEXT；不引入 Redis、Celery、Elasticsearch 或第二套权限数据库。
- Python 单 worker 处理 PDF/TXT/Markdown，使用 C++ 内部受认证接口领取任务、读取固定版本和提交结果；不能凭模型参数或任意磁盘路径读文件。
- 解析、本地关键词、向量分别记录状态。先交付本地处理闭环，再接真实向量与混合检索；关键词降级不算 M2 完成。
- 不在 M2 实现 Agent、MCP 工具、归档确认或报告生成。

## 2. 分块与引用

片段携带 `file_id`、`version_id`、`chunk_id`、`source_sha256`、解析器修订、原文和来源位置。PDF 页码是从 1 起的物理页；TXT/Markdown 使用从 1 起的行号，并附规范化文本的字符偏移 `[start, end)`，以区分同一长行内的多个片段。字符按 Python Unicode 码点计数，不是 UTF-8 字节或浏览器 UTF-16 偏移。

首个独立增量只实现纯本地 TXT/Markdown 解析函数，不开放 HTTP、不连接数据库、不读取文件路径、不调用模型。输入为受控读取后的 bytes 与可信文件/版本 ID。严格 UTF-8，允许开头 BOM，将 CRLF/CR 统一为 LF，其余内容（包括 Markdown 标记和文档中的指令）原样保留。拒绝二进制控制字符、无文本和超限输入；不得静默丢字或截断后报告完成。

文本默认上限：输入 8 MiB、规范化文本 2,000,000 个字符、每块 1,200 个字符、最多 2,000 块；这些是保守的实现限制，不是已测性能指标。每块连续、不重叠，保留空白与换行。稳定 ID 由解析器修订、文件/版本 ID、原始内容 SHA-256 与字符区间计算，不包含任务重试次数或检索查询。解析器/分块规则升级不得覆盖已持久化的历史引用。

PDF 增量使用固定版本的成熟文本提取库（已验证 pypdf 6.21.0 与当前 Python 3.10 兼容），不自写 PDF 解析器、不做 OCR。加密不可读、损坏、无可提取文字、页数或文本超限分别失败。初始 PDF 大小 8 MiB、页数 300；在独立受限子进程执行，限制内存、CPU 和墙钟时间，不能仅凭压缩前文件大小防止解压耗尽。单页内容及嵌套 Form 解压总量限制 16 MiB，同一 Form 只计一次；库发出提取警告时拒绝发布部分结果。没有文字的物理页单独报告，不从输出中静默省略覆盖状态。

## 3. 任务与发布

扩展已有 `processing_jobs`，不再另建同用途队列。领取通过数据库事务进行；任务绑定不可变版本、原文哈希和 attempt 标识，队列与执行并发有界。首版执行并发 1、待处理队列上限 100；队列满时保留文件可管理，并显示繁忙/未排入，不无限增长后台执行工作。

流程：排队 → 执行 → 完成/失败；运行中重启 → 中断；排队或未提交执行可取消。失败/中断允许有权限用户显式重试，产生新 attempt；旧 attempt 不得续写。上传完成只提交已有版本/任务元数据，不同步解析。

结果先暂存，C++ 在事务内重新校验 attempt、任务状态、文件未删除和当前版本后原子发布。本地解析/关键词成功不掩盖向量失败；内部资料向量状态为不适用。旧任务、取消任务、超限和部分输出都不能发布成功。启动恢复和重试策略不承诺从任意内部步骤续跑。

新版提交立即排除旧版默认正文检索，即使新版尚未解析；删除立即排除；移动只改变目录过滤；还原只复用仍有效且就绪的索引。历史引用保留原版本，不自动跳转到新版本；所有读取重新鉴权。

## 4. 检索与外发边界

普通元数据搜索可以发现未解析文件；正文检索连接 C++ 权威当前版本与权限状态，不直接相信索引副本。关键词测试覆盖中文、英文、短查询、特殊字符及 ngram/停用词边界，不使用拼接 SQL。

向量方案必须能生成真实语义向量，再与关键词候选按稳定片段 ID 去重融合，返回有限结果及覆盖范围。向量服务失败明确返回关键词降级，不能伪造向量或将聊天回答当 embedding。向量实现/供应商的选择单独在接入前核对支持、资源与费用；在此之前本地闭环不阻塞，但整个 M2 不可宣告完成。

DeepSeek 密钥仅保留在用户指定的仓库外受保护配置。此前 `/models` 认证成功只证明该请求可用，不证明向量端点、生成额度或数据保留条款已验证。本地解析不需要密钥。后续远程调用必须由 C++ 再次确认具体版本的外发批准、当前权限与删除状态；未批准版本的正文、摘要、元数据不能进入远程调用。用户提供 API key 不等于批准外发所有文档。

## 5. 验证和运行约束

每次只执行一个可验证增量，测试先失败再实现。先小型纯 Python 测试，再有界 PDF 子进程、隔离 MySQL、HTTP 与界面集成，最后 M2 阶段验收。不得用纯函数测试声称后台自动索引已接通。

当前 ECS 不并发执行重型构建、数据库验收和解析负载。重型测试沿用已核验的 systemd 上限：MemoryHigh=1200M、MemoryMax=1600M、MemorySwapMax=0、CPUQuota=100%、TasksMax=256、Nice=10；当前磁盘 /dev/vda 读写各 5 MB/s、200 IOPS。单次诊断至多 15 分钟；可用内存低于 512 MiB 时停止本次测试单元。纯文本小夹具测试另用更低的进程内存/CPU 限制，无需启动数据库或浏览器。

M2 必须具备：三种格式、可观察的持久任务与人工重试、独立状态、真实混合检索及明确降级、当前版本防陈旧发布、固定版本引用、越权/删除/撤销外发测试。测试记录写明真实执行范围，不改写 M1 已归档证据。

## 6. 实施顺序

1. TXT/Markdown 纯本地解析、稳定引用数据和边界测试。
2. 受限 PDF 提取与物理页定位。
3. MySQL 迁移、C++ 任务/状态/发布接口与单 worker，集成取消、重试和重启中断。
4. 本地关键词和元数据检索、固定版本片段读取及页面接入。
5. 经验证的真实向量来源、混合检索、外发撤销竞态和完整 M2 验收。
