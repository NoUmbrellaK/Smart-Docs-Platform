# M3 MCP 与 Agent：边界与首个增量

2026-10-18 用户明确开始 M3，并取消“当前阶段完成后停止”。沿用已批准的自主实施、当前服务器执行、正常提交推送及节省 token 要求。需求文档仍是唯一验收基线；M2 关闭提交为 c0c257b。本设计不是 M3 完成声明。

## 总体路径与取舍

采用 Python 官方 MCP SDK 作为协议层，C++ 继续负责权限、版本和业务事务，Python 负责有界 Agent 编排。先独立验证搜索/读取，再接有预算的 DeepSeek 多步任务，最后补齐全部五项工具契约及与 M4 的业务接线。SDK 版本、内部 Streamable HTTP 身份绑定及模型参数在对应增量核验后锁定，不在本次安装依赖或开放服务。

不采用 Python 拉取普通搜索结果后再过滤：候选、数量和名称已经越过边界，且分页会失真。不自研 MCP 协议或第二套权限数据库。选择复用 C++ 检索事务，在 SQL 候选、覆盖计数和返回前锁定读中强制具体版本外发批准。

后续 Agent 任务的身份、项目、允许版本范围、目录/清单授权来自可信服务端；模型不得提供身份、批准记录或任意操作 ID。每次工具返回和模型请求都重新校验依赖，文档仅作为不可信数据。任务与操作 ID 持久化；重启标记中断，取消后不发起新步骤；写操作响应不明确时查询既有结果。只读工具先可用不等于五工具全部实现，空壳写工具不作为完成证据。

## 首个增量：供工具使用的 C++ 只读外发门禁

已有普通 metadata/keyword 搜索和 document/chunk 读取允许内部资料，不能直接用于远程上下文。增加并复用以下接口，不改变普通工作台行为：

- POST `/api/v1/projects/{project_id}/remote-ai/search`：已有搜索 JSON；三种模式全部强制文件策略允许外发且当前版本已批准；默认/最多 10 项，沿用分页、覆盖和降级字段。身份来自现有 Cookie，POST 要求同源，JSON 不接受 user_id、approved 或绕过参数。
- GET `/api/v1/projects/{project_id}/files/{file_id}/versions/{version_id}/remote-ai/document`：读取固定版本状态，不隐式替换新版。
- GET 同一版本前缀的 `/remote-ai/chunks/{chunk_id}`：读取一个最长 1200 Unicode 字符的稳定片段。

读取在成员/文件/版本共享锁保护下核查文件策略和该版本批准，未批准与不存在统一 404，不返回名称、数量或正文。历史版本仅在被明确指定且仍获批准时可读；后续新任务/模型出口还需验证任务允许范围，不能把此接口成功当永久授权。新版本默认未批准，文件整体改为内部管理阻止全部版本读取。删除、跨项目、撤销成员沿用已有检查。

本增量不实现任务限定范围、模型出口、分页整篇读取、MCP 协议、Agent UI、归档与报告。它是后续接入的必要安全基础，不能单独满足 T-18 或宣称已有端到端 Agent。
